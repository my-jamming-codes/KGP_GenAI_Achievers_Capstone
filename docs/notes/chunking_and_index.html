How a page becomes chunks, and chunks become search results

Every example below is paragraph 58 of the RBI Housing Finance Companies Directions, the paragraph behind the 90 / 80 / 75 percent LTV limits. Code: src/ingest/parse.py for splitting and src/index/hybrid.py for the index.

THE WHOLE PATH

STAGE 2Cut at paragraph numbers

The splitter reads the page line by line. A line starts a new paragraph only if it begins with a number and a dot, and the number makes sense after the previous one. Everything else stays with the paragraph above. This is the example run live in your browser with the same rule as split_paragraphs.

Line on the pageVerdictWhy

The rule: a line counts as paragraph n when current ≤ n ≤ current + 60, and it is not the same plain number again. Nested lists such as "1. Policy for…" restart at 1, so they fail the test and stay inside paragraph 58. The line "1. Policy for valuation…" here is an illustration of that case. Letters are allowed, so 13G. is paragraph 13G.

STAGE 3Keep each chunk to 220 words

Paragraph 58 as it really is in the data: eight lines, with the number of words in each. The code adds lines to a chunk until the next line would pass the limit, then starts a new chunk. It never cuts inside a line. Move the slider to see where the cut falls.

220

At 220 words, the first seven lines come to 211 words. The eighth, a 13-word heading of the next section ("E. Concentration of credit…"), would make 224, so it becomes its own chunk HFC-MD/58#1. That is why paragraph 58 has two chunks. Slide above 224 and it becomes one.

STAGE 4One chunk is one line of chunks.jsonl

43,336 lines like this in data/index/chunks.jsonl. The line number matters: the index below is built so that line N of the vectors belongs to line N of this file.

STAGE 5Build the index: three stores from one file

If a vector were stored in the wrong order, a search would return the wrong paragraph text. That is why the build keeps one ordered file and a recorded corpus version. It reuses an old vector when a chunk's text is unchanged, so a re-parse only embeds what changed.

STAGE 6Search: two lists, merged, then re-read carefully

Meaning search catches "borrowing limit" for "LTV"; keyword search catches the exact "75" and "₹30 lakh". Merging by rank rather than by raw score avoids comparing two different scales. The lender filter is why a housing finance case never sees the bank Directions. Code: HybridIndex.search, hybrid.py:210.
